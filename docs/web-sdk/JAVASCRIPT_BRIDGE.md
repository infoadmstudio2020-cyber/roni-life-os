# RONiLiFEOS — JavaScript Bridge Reference

**Verified against source:** `native-web-bridge-sdk`, `native-runtime-ui/web/WebViewHost.java`
**Bridge version:** 1.0 (protocol `REQUEST` / `RESPONSE` / `ERROR` / `EVENT` / `PING`)

This document describes the **only** transport that exists between a web app and RONiLiFEOS native code. Everything else in the SDK documentation is built on top of it.

---

## 1. What the native side injects

When a `WebViewHost` is created, `WebViewHost.attachBridge()` performs three steps:

| Step | Native call | Effect |
| --- | --- | --- |
| 1 | `webView.addJavascriptInterface(new NativeJavascriptInterface(bridge), "NativeRuntimeBridge")` | Creates `window.NativeRuntimeBridge` with `postMessage(String)` and `ping()` |
| 2 | `bridge.setOriginProvider(...)` | Native can read the current page origin for validation |
| 3 | `bridge.setWebEvaluator(...)` | Native can push scripts into the page |

After every `onPageFinished`, `WebViewHost.injectBootstrap()` evaluates `WebBridge.getBootstrapScript()`, which defines **`window.NativeRuntimeBridgeClient`**.

> The interface name is configurable through `BridgeConfig.interfaceName(...)` / `WebHostConfig.builder().bridgeInterfaceName(...)`. The default — and the value used by `RONiLiFEOS` — is `NativeRuntimeBridge`. If a host changes it, the client object becomes `window.<name>Client`.

### 1.1 Objects available in the page

```js
window.NativeRuntimeBridge        // native object (postMessage, ping) — do not call directly
window.NativeRuntimeBridgeClient  // JS client — this is what you use
```

`NativeRuntimeBridgeClient` exposes exactly five members:

| Member | Signature | Behaviour |
| --- | --- | --- |
| `call` | `call(action: string, payload?: object): Promise<any>` | Sends a `REQUEST`, resolves with the native `payload` |
| `ping` | `ping(): string` | Returns `"pong"` from native, or `"pong_fallback"` |
| `on` | `on(topic: string, listener: (payload) => void): void` | Subscribes to a native `EVENT` |
| `off` | `off(topic: string, listener): void` | Unsubscribes |
| `_handleNativeMessage` | `_handleNativeMessage(rawJson: string): void` | Internal — called by native, do not call |

There is **no** `NativeRuntime.ui`, `NativeRuntime.device` or `NativeRuntime.storage` object injected by native code. Any namespaced facade you see in `examples/` is a **JavaScript wrapper** written on top of `call()`. See §7.

## 2. Message envelope

Every message is a JSON string with this shape:

```json
{
  "id": "req_1732091234567_1",
  "type": "REQUEST",
  "action": "ui.showToast",
  "payload": { "message": "Hello" },
  "error": null,
  "success": true,
  "timestamp": 1732091234567
}
```

| Field | Type | Present in | Notes |
| --- | --- | --- | --- |
| `id` | string | all | Generated by the client as `req_<epochMs>_<counter>` |
| `type` | `REQUEST` \| `RESPONSE` \| `ERROR` \| `EVENT` \| `PING` | all | `BridgeMessageType` |
| `action` | string | all | For `EVENT` this is the **topic** |
| `payload` | object | `REQUEST`, `RESPONSE`, `EVENT`, `PING` | Never `null` on the wire; defaults to `{}` |
| `error` | string \| null | `ERROR` | Human-readable message; the machine code is usually the prefix |
| `success` | boolean | all | `false` only on `ERROR` |
| `timestamp` | number | all | Epoch milliseconds |

### 2.1 Response

```json
{ "id": "req_...", "type": "RESPONSE", "action": "ui.showToast",
  "payload": { "shown": true }, "success": true, "timestamp": 1732091234600 }
```

The client resolves the pending promise with `msg.payload` — **not** the whole envelope. So `await call('ui.showToast', {...})` yields `{ shown: true }`.

### 2.2 Error

```json
{ "id": "req_...", "type": "ERROR", "action": "ui.showToast",
  "error": "UNKNOWN_ACTION: Action not supported: nope", "success": false }
```

The client rejects with `new Error(msg.error)`. The error **code is the prefix before the first `:`** for most handlers, but not all — see §6.

### 2.3 Event

```json
{ "id": "<uuid>", "type": "EVENT", "action": "ui.confirm",
  "payload": { "confirmed": true }, "success": true }
```

The client dispatches to every listener registered for `msg.action`.

### 2.4 Ping

`type: "PING"` is answered natively with `{ pong: true, serverTime: <epochMs> }`. The JS client does not use it; `NativeRuntimeBridgeClient.ping()` calls the native `ping()` method directly and returns `"pong"`.

## 3. Action naming

`WebBridge.handleWebMessage()` accepts three equivalent forms:

| Form | Example | Parsed path | Parsed action |
| --- | --- | --- | --- |
| Dot | `ui.showToast` | `/ui` | `showToast` |
| Slash | `/ui/showToast` | `/ui` | `showToast` |
| Bare | `showToast` | `/showToast` | `showToast` |

The path is normalised to a single leading slash and matched by `PatternRouteMatcher`, which strips the leading slash on both sides. Therefore `ui`, `/ui` and `ui/` all resolve to the same handler.

**Recommendation:** always use the dot form (`namespace.action`). It is the form used by every handler's own `normalizeAction()` helper and by all examples.

### 3.1 Registered routes

| Route | Handler | Actions | Registered by |
| --- | --- | --- | --- |

## 4. Security gates

`WebBridge.handleWebMessage()` applies four gates **in this order**. A message that fails a gate never reaches a handler.

### Gate 1 — size

```java
int size = rawJson.getBytes(StandardCharsets.UTF_8).length;
if (size > config.getMaxMessageBytes()) { /* PAYLOAD_TOO_LARGE */ }
```

Default limit: **1 048 576 bytes (1 MiB)**. The rejection is emitted with `id: "unknown"`, so the originating promise is **not** rejected — it will time out instead. Keep payloads small; send file content through `filemanager.writeFile` (base64) or `storage.set` in chunks.

### Gate 2 — origin

Enabled by default (`BridgeConfig.requireOriginValidation = true`). The allow-list starts with `https://appassets.androidplatform.net`. `WebViewHost.trustBridgeOrigin()` adds the origin of the source it is about to load, so a per-project host such as `https://myproject-1a2b3c4d.runtime.local` is trusted for that page only.

Failure produces:

```json
{ "type": "ERROR", "error": "ORIGIN_REJECTED: https://evil.example" }
```

A `null` origin is never allowed. An empty allow-list allows nothing. `addAllowedOrigin("*")` disables the check explicitly.

### Gate 3 — message validity

`BridgeSecurityValidator.isMessageValid()` rejects a missing/blank `action` or a malformed payload:

```json
{ "type": "ERROR", "error": "Security validation failed" }
```

### Gate 4 — route existence

If no handler is registered for the path:

```json
{ "type": "ERROR", "error": "ROUTE_NOT_FOUND: No handler registered for route: /foo" }
```

This is deliberate: an unknown route fails loudly instead of echoing the payload back as success.

## 5. Timeouts

| Layer | Value | Source |
| --- | --- | --- |
| Native pending-request sweep | `BridgeConfig.timeoutMs`, default **10 000 ms** | `WebBridge.startSweeper()` |
| Sweep interval | `clamp(timeoutMs, 100, 5000)` ms | `WebBridge.startSweeper()` |
| `web.evaluate` main-thread wait | 10 s | `NativeWebCommandHandler` |
| `web.evaluate` JS result wait | 3 s | `NativeWebCommandHandler` |
| Router `dispatchSync` | 30 s | `NativeRouter` |

When the native sweep expires a request it emits:

```json
{ "id": "req_...", "type": "ERROR", "action": "ui.showToast", "error": "REQUEST_TIMEOUT" }
```

The JS client has **no** timeout of its own. If you need one, wrap `call()` — see §7.2.

## 6. Error codes you will actually see

| Code | Emitted by | Meaning |
| --- | --- | --- |
| `ROUTE_NOT_FOUND` | `WebBridge` | No handler for the path |
| `REQUEST_TIMEOUT` | `WebBridge` sweeper | Handler did not answer within `timeoutMs` |
| `PAYLOAD_TOO_LARGE` | `WebBridge` | Message exceeded 1 MiB |
| `ORIGIN_REJECTED: <origin>` | `WebBridge` | Page origin not in the allow-list |
| `Security validation failed` | `WebBridge` | Missing action / invalid envelope |
| `UNKNOWN_ACTION` | most handlers | Action not in the handler's switch |
| `MISSING_ACTION` | `ui`, `web`, `device`, `theme`, `runtime`, `devtools` | Empty action |
| `INVALID_REQUEST` | `ui`, `storage`, `device`, `web`, `logger`, `devtools` | Null request |
| `INTERNAL_ERROR` | most handlers | Uncaught exception inside the handler |
| `ACTIVITY_UNAVAILABLE` | `device` | No Activity attached to `NativeUIHost` |
| `STORAGE_UNAVAILABLE` | `storage` | `StorageEngine` not initialised |
| `RESERVED_KEY` | `storage` | Key starts with `__p:` in the legacy namespace |
| `MAIN_THREAD_TIMEOUT` / `MAIN_THREAD_UNAVAILABLE` | `web` | WebView command could not run on the UI thread |
| `MAIN_THREAD_BLOCKED` | `web.evaluate` | Called from the main thread |
| `NOTIFICATION_*` | `notification` | See `NOTIFICATION_API.md` |
| `CAMERA_*` | `camera` | See `NATIVE_API_REFERENCE.md` §12 |
| `FILE_*` | `filemanager` | See `NATIVE_API_REFERENCE.md` §13 |
| `AUTOMATION_*` | `automation` | See `BACKGROUND_SERVICES_API.md` |
| `NETWORK_ERROR` / `INVALID_URL` / `UNSUPPORTED_SCHEME` / `UNSUPPORTED_METHOD` / `FORBIDDEN_HEADER` | `network` | See `NATIVE_API_REFERENCE.md` §9 |

> **Important:** the JS client rejects with `new Error(msg.error)`. It does **not** attach a `.code` property. Parse the code yourself:

```js
function codeOf(error) {
  const text = String(error && error.message ? error.message : error);
  const match = text.match(/^([A-Z][A-Z0-9_]{2,})/);
  return match ? match[1] : 'NATIVE_ERROR';
}
```

## 7. Writing a safe wrapper

### 7.1 Availability detection

```js
export function available() {
  return typeof window.NativeRuntimeBridgeClient !== 'undefined'
      && typeof window.NativeRuntimeBridgeClient.call === 'function';
}
```

`available()` is `false` in a desktop browser, in a plain WebView without the SDK, and **before** `onPageFinished` fires. Always guard.

### 7.2 `call()` with a timeout and a normalised error

```js
const DEFAULT_TIMEOUT = 15000;

export function call(action, payload = {}, timeoutMs = DEFAULT_TIMEOUT) {
  if (!available()) {
    const error = new Error('NATIVE_UNAVAILABLE');
    error.code = 'NATIVE_UNAVAILABLE';
    error.action = action;
    return Promise.reject(error);
  }

  return new Promise((resolve, reject) => {
    let settled = false;
    const timer = setTimeout(() => {
      if (settled) return;
      settled = true;
      const error = new Error('CLIENT_TIMEOUT');
      error.code = 'CLIENT_TIMEOUT';
      error.action = action;
      reject(error);
    }, timeoutMs);

    window.NativeRuntimeBridgeClient.call(action, payload).then(
      (result) => {
        if (settled) return;
        settled = true;
        clearTimeout(timer);
        resolve(result);
      },
      (error) => {
        if (settled) return;
        settled = true;
        clearTimeout(timer);
        const text = String(error && error.message ? error.message : error);
        const match = text.match(/^([A-Z][A-Z0-9_]{2,})/);
        const normalized = new Error(text);
        normalized.code = match ? match[1] : 'NATIVE_ERROR';
        normalized.action = action;
        reject(normalized);
      }
    );
  });
}
```

### 7.3 Events

```js
export function on(topic, handler) {
  if (!available()) return () => {};
  window.NativeRuntimeBridgeClient.on(topic, handler);
  return () => window.NativeRuntimeBridgeClient.off(topic, handler);
}
```

`on()` returns an unsubscribe function. Native never removes listeners for you; a page reload clears them because the whole JS context is replaced.

### 7.4 Feature probing

Because a route can be absent (devtools in release builds, camera when the platform engine is not initialised), probe before use:

```js
const PROBES = {
  theme:      ['theme.getTheme', {}],
  security:   ['security.diagnostic', {}],
  analytics:  ['analytics.getStats', {}],
  devtools:   ['devtools.getHealth', {}],
  platform:   ['platform.health', {}],
  logger:     ['logger.getLevel', {}],
  service:    ['service.list', {}],
  storage:    ['storage.keys', {}],
  notification: ['notification.status', {}],
  automation: ['automation.getStatus', {}],
  camera:     ['camera.getCapabilities', {}],
  filemanager:['filemanager.getStorageInfo', {}],
  network:    ['network.request', { url: 'https://example.com' }]
};

const cache = new Map();

export async function isSupported(namespace) {
  if (cache.has(namespace)) return cache.get(namespace);
  const probe = PROBES[namespace];
  if (!probe) return false;
  let supported = true;
  try {
    await call(probe[0], probe[1]);
  } catch (error) {
    supported = error.code !== 'ROUTE_NOT_FOUND' && error.code !== 'NATIVE_UNAVAILABLE';
  }
  cache.set(namespace, supported);
  return supported;
}
```

A probe that fails with `UNKNOWN_ACTION` still proves the route exists — only `ROUTE_NOT_FOUND` means "not installed".

## 8. Second JavaScript interface: `RONiDownload`

`WebViewHost` registers a **second, independent** interface when downloads are enabled:

```java
webView.addJavascriptInterface(new DownloadCenter.JsBridge(context), "RONiDownload");
```

| Method | Signature | Effect |
| --- | --- | --- |
| `saveBase64` | `RONiDownload.saveBase64(base64, fileName, mime)` | Decodes base64 and writes it to the public Downloads collection |
| `download` | `RONiDownload.download(url, fileName)` | Enqueues a `DownloadManager` request |

These are **synchronous, fire-and-forget** calls with no return value and no error channel. They are not part of the bridge protocol and do not appear in `NativeRuntimeBridgeClient`.

```js
// Save a generated file
const base64 = btoa(unescape(encodeURIComponent(csvText)));
window.RONiDownload.saveBase64(base64, 'report.csv', 'text/csv');
```

`RONiDownload` is only present when `WebHostConfig.isDownloadsEnabled()` is `true` (the default). Guard with `typeof window.RONiDownload !== 'undefined'`.

## 9. Lifecycle of the bridge

```
WebViewHost constructor
  └─ attachBridge()            addJavascriptInterface + originProvider + webEvaluator
       │
loadSource(source)
  └─ trustBridgeOrigin(host)   allow-list += https://<host>
       │
onPageStarted
       │
onPageFinished
  ├─ injectBootstrap()         defines window.NativeRuntimeBridgeClient
  └─ installErrorReporter()    (only when a diagnostics listener is attached)
       │
  ... page runs, calls call() ...
       │
onDestroy()
  ├─ bridge.clearWebEvaluator()
  ├─ bridge.clearOriginProvider()
  └─ webView.removeJavascriptInterface("NativeRuntimeBridge")
```

Consequences for your app:

1. **Do not call the bridge from `<head>` synchronously.** `NativeRuntimeBridgeClient` does not exist until `onPageFinished`. Use `DOMContentLoaded` plus a retry loop, or the `ready()` helper in `WEB_APP_DEVELOPER_GUIDE.md`.
2. **A page reload re-injects the client.** Pending promises from the old page are lost; native will drop their responses (`Dropping response for unknown or expired request`).
3. **`onDestroy` clears the evaluator**, so native events emitted after the host is destroyed are silently discarded.

## 10. What the bridge does *not* do

| Not supported | Reality |
| --- | --- |
| `window.NativeRuntime.ui.*` | Not injected. Build it yourself on `call()`. |
| Promise rejection with `.code` | Native sends a string; the client wraps it in `Error(message)`. |
| Binary payloads | Everything is JSON text. Use base64 strings. |
| Streaming responses | One request → one response. |
| Server-sent events from native | Use `on(topic, ...)` instead. |
| Calling native from a `file://` page | Origin validation rejects it unless the host explicitly allows the origin. |
| `postMessage` on `window` | The bridge uses `addJavascriptInterface`, not `window.postMessage`. |
